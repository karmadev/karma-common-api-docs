The integration, spelled out

Everything the demo does above, as copy-pasteable contract.

  1. Get an API key & location ID

    Ask Karma for a key scoped to your location(s) with surplus.create, surplus.read, and webhooks.create. Your location ID is in the Merchant dashboard under Settings → Integrations. Every request carries it in the header X-API-Key.

  2. Push surplus when service ends

    One call per item (or up to 500 in a bulk call): POST /api/v1/locations/:locationId/helpers/surplus/add. Pass your own externalId (SKU/PLU) — Karma finds-or-creates the catalogue item, then upserts today's surplus quantity. It's live for nearby guests immediately.

  3. Register a webhook once

    POST /api/v1/webhooks/subscriptions with your HTTPS URL, the events you care about, and a signing secret. Karma will POST every matching event to you.

  4. Receive the sale, decrement your stock

    When a guest buys, Karma sends order.created (the pickup order) then tab.payment_completed (money settled). Verify the X-Webhook-Signature HMAC, then knock the sold quantity off your POS. No polling.

  5. Push absolute quantities, not deltas

    Sold 3 in-store after pushing 8? Push quantity: 5. Karma replaces the number — the same upsert keeps both systems honest all day.

The mental model: REST is how you tell Karma about surplus. Webhooks are how Karma tells you what happened to it. Together they keep one truth about stock across two systems.
MethodEndpointWhat it does
POST/api/v1/locations/:locationId/helpers/surplus/addFind-or-create item by externalId and upsert today's surplus in one call. The main endpoint.

push-surplus.ts · SDK
import { createKarmaClient } from '@karmalicious/karma-api-js'

const client = createKarmaClient({
  apiKey: process.env.KARMA_API_KEY!,
  locationId: 1234,
})

const { surplusEntry, item } = await client.surplus.add({
  item: {
    externalId: 'sku-pasta-bolognese',   // your stable SKU/PLU
    title: 'Pasta Bolognese',
    basePriceCents: 12900,               // full price, in cents
    category: 'FOOD',
    allergens: ['GLUTEN', 'MILK'],
  },
  quantity: 5,               // absolute count left — not a delta
  discountPercentage: 50,    // min 50; or overridePriceCents
  date: '2026-07-16',        // sell window: midnight → close
})

console.log(surplusEntry.id, item.created)

externalId is the join key. Keep it stable (SKU / PLU / barcode) — never a name or timestamp. Change it and you create a duplicate item.

These are the real events the platform emits. Register once, then Karma POSTs them to your URL. The three a surplus POS lives on are at the top.

EventResourceFires whenUse it to…
surplus.addedsurplusA surplus entry is created (e.g. your push).Confirm the listing is live. Payload: { locationId, locationName, entryId, addedAt }.
order.createdorderA guest's order (incl. a surplus pickup) is sent.Fire a prep ticket & earmark stock. Items carry Karma's itemId — map to your SKU via the push response.
tab.payment_completedtabPayment settles successfully.Record the sale & decrement POS stock. Payload: amountCents, paymentMethod, pspReference, itemIds…
order.completedorderOrder marked complete / picked up.Close the loop in your POS.
order.cancelledorderAn order is cancelled.Release earmarked stock.
tab.payment_failedtabA payment attempt fails.Don't count the sale; keep stock available.
inventory.created / updated / deletedinventoryAn item is created, edited, or removed.Mirror catalogue changes on your side.
Mapping note: order.created items reference Karma's internal itemId, not your externalId. Keep the itemId ↔ externalId pair from each surplus/add response so you can resolve sales back to your own SKUs.

receiver.ts · verify & handle
import express from 'express'
import crypto from 'crypto'

const app = express()
app.use('/webhooks/karma', express.raw({ type: 'application/json' }))

app.post('/webhooks/karma', (req, res) => {
  const sig = req.headers['x-webhook-signature']
  const expected = crypto.createHmac('sha256', process.env.WEBHOOK_SECRET!)
    .update(req.body).digest('hex')
  if (sig !== expected) return res.status(401).send('bad signature')

  res.status(200).send('OK')            // ack fast (< 5s)

  const evt = JSON.parse(req.body.toString())
  switch (evt.event) {
    case 'surplus.added':          // listing is live on Karma
      pos.markListedOnKarma(evt.data.entryId); break
    case 'order.created':          // guest ordered — items use Karma itemId
      evt.data.items.forEach(li =>
        pos.earmark(skuFor(li.itemId), li.quantity)); break
    case 'tab.payment_completed':  // money settled — book the sale
      pos.recordSale(evt.data.itemIds, evt.data.amountCents,
                     evt.data.pspReference); break
    case 'order.cancelled':
      pos.releaseEarmark(evt.resourceId); break
  }
})

// skuFor() reads the itemId → externalId map you saved at push time.

Retry-safe: webhooks retry on non-200 (5 attempts, exponential backoff). Dedupe on event.id and treat handlers as idempotent. Delivery rides Google Cloud Pub/Sub → a delivery Cloud Function, so order isn't guaranteed — don't assume tab.payment_completed arrives after order.created.

Authentication

Every request is authenticated with an API key in the X-API-Key header — no OAuth dance. Keys are scoped to specific locations and permissions.

HeaderX-API-Key: karma_live_…
ScopePer location ID — one key can cover many locations
Location IDPath param :locationId; Merchant dashboard → Settings → Integrations

Permissions this key needs

Dot notation, resource.action. The whole demo runs on the three at the top.

PermissionFor
surplus.createPush surplus — also covers find-or-create of the item, no separate inventory grant needed
surplus.readList what you pushed
webhooks.createRegister your endpoint (+ webhooks.read/update/delete to manage it)
surplus.update / surplus.deleteAdjust quantity or pull an entry
— none —Receiving order.created / tab.payment_completed: no scope; auth is the HMAC signature
You do not need orders.create — guests create orders, your POS only receives them. Add it only if the POS pushes its own orders into Karma. Add orders.read/purchases.read only if you'd rather REST-poll than trust webhooks.
